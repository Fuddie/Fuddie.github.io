SNOWFLAKE + dbt ANALYTICS ENGINEERING PROJECT

Olist Analytics

A production-oriented analytics engineering pipeline built on Snowflake and dbt Cloud using the Brazilian Olist e-commerce dataset. The project covers layered modelling, dimensional marts, ingestion-based incremental processing, automated data tests, pull-request CI, workload isolation, service-user authentication and scheduled production deployment.

Data: public Olist e-commerce data. The project is independent portfolio work and contains no employer or customer data.

IMPLEMENTATION

Production engineering decisions built into the project.

INCREMENTAL PROCESSING

Ingestion-based watermarks

The original business-date lookback was replaced with persistent ingestion metadata. Watermarks propagate from RAW into downstream models and drive incremental Snowflake MERGE operations.

RAW._LOADED_AT ↓ staging._loaded_at ↓ intermediate.record_loaded_at ↓ incremental MERGE
DIMENSIONAL MODELLING

Two fact grains

fct_orders provides one row per order while fct_order_items provides one row per order-item key. This preserves order KPIs while correctly connecting product and seller dimensions to transactional activity.

ENVIRONMENT ISOLATION

Separate DEV and PROD compute

Development uses DEV_WH and production uses DBT_PROD_WH. Production models are also split across staging, intermediate and mart schemas rather than sharing one catch-all schema.

SECURITY

Service identity and RBAC

Production runs through DBT_USER and DBT_ROLE with RSA key-pair authentication. A separate read-only analytics role limits consumer access to the production marts.

QUALITY

Structural and business tests

Tests cover keys, relationships, accepted values, fact grains and non-negative commercial values. Known timestamp and payment reconciliation anomalies are surfaced as warnings instead of silently ignored.

DELIVERY

Feature branch → CI → production

Changes move through feature branches and pull requests. GitHub Actions validates dbt project parsing and graph integrity before merge, followed by DEV validation and a controlled dbt Cloud production deployment.
