FINTECH ANALYTICS ENGINEERING CASE STUDY

WalletFlow Analytics

A synthetic digital-wallet project showing how raw customer, wallet and transaction data can be transformed into tested data products with incremental processing, late-arriving-data protection, governed engagement KPIs, cohort retention and pull-request quality checks.

Portfolio project: WalletFlow is fictional and uses generated data only. It is designed to demonstrate analytics engineering patterns without exposing employer or customer data.

ENGINEERING DECISIONS

Patterns that make the project easier to trust and operate.

MODEL CONTRACTS

Explicit column selection

Transformation and test SQL avoid SELECT *. Each model names the fields it depends on, making upstream schema changes visible.

select transaction_id, customer_id, amount_ngn, status, created_at from {{ ref('stg_transactions') }}
INCREMENTAL RELIABILITY

Late-arriving transactions

The transaction fact re-reads a configurable three-day window on incremental runs. Because transaction_id is the MERGE key, recent rows can be reprocessed without creating duplicates.

vars: incremental_lookback_days: 3
TESTING

Business-rule checks

Tests cover keys, relationships, accepted values, positive amounts, transaction-status reconciliation, composite grains and engagement logic.

  • Average DAU cannot exceed MAU.
  • Retained customers cannot exceed the previous-month population.
  • Month-zero cohort retention must equal 100%.
  • Retention and success rates must remain between 0 and 1.
CONTINUOUS INTEGRATION

Pull-request quality checks

GitHub Actions rejects SELECT * in models/tests. With BigQuery credentials configured, the workflow also loads synthetic seeds, runs dbt build, and checks source freshness before changes are accepted.

PRODUCT ANALYTICS

DAU, MAU & stickiness

DAU counts distinct daily transacting customers. MAU counts distinct monthly customers. Average DAU divided by MAU provides a simple engagement-frequency or “stickiness” measure.

RETENTION

Two retention views

The monthly engagement mart measures whether last month's active users returned. A separate cohort model groups customers by their first successful transaction and follows their later successful activity.

INTERVIEW VERSION

How I explain WalletFlow in under a minute.

“I built WalletFlow as a synthetic fintech analytics engineering project. I structured generated wallet data into source, staging, intermediate and mart layers; built an incremental BigQuery fact with a configurable lookback for late-arriving events; added tested DAU, MAU, stickiness, month-over-month retention and cohort retention; and added CI so SQL conventions and dbt quality checks can run before changes reach main. The goal is to create a governed analytics layer rather than rebuild metric logic inside every dashboard.”
