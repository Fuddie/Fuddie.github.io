PRODUCTION-ORIENTED ANALYTICS ENGINEERING

Snowflake + dbt

An end-to-end analytics engineering project built on Snowflake and dbt Cloud using the Brazilian Olist public e-commerce dataset. The project covers raw ingestion metadata, layered transformations, dimensional modelling, incremental MERGE pipelines, testing, CI, security, environment isolation and scheduled production orchestration.

Data: Brazilian E-Commerce Public Dataset by Olist. The project uses public historical data; no employer or customer data is included.

IMPLEMENTATION DETAILS

What makes the project production-oriented.

DIMENSIONAL MODELLING

Two transactional grains

fct_orders is one row per order, while fct_order_items is one row per order item. The second fact properly connects product and seller dimensions without forcing one-to-many detail into the order grain.

INCREMENTAL PROCESSING

Ingestion-based watermarks

Incremental models use record_loaded_at, propagated from RAW _LOADED_AT, rather than only the order purchase date. This allows historical business records to be reprocessed when they are loaded or changed later.

RAW._LOADED_AT ↓ staging._loaded_at ↓ intermediate.record_loaded_at ↓ Snowflake MERGE
ENVIRONMENT ISOLATION

Separate DEV and PROD compute

Development uses DEV_USER / DEV_ROLE / DEV_WH. Production uses DBT_USER / DBT_ROLE / DBT_PROD_WH. Models are also separated into staging, intermediate and mart schemas in each environment.

SECURITY

Service-user key-pair authentication

The production dbt service user authenticates with an encrypted RSA key pair instead of a password. A separate read-only analytics role is provided for mart consumers.

TESTING & OBSERVABILITY

Grain and business-rule checks

Tests cover uniqueness, nullability, relationships, accepted values, order-item composite grain, non-negative commercial values, timestamp anomalies and payment reconciliation. Business anomalies can surface as warnings without unnecessarily stopping every deployment.

CI & DEPLOYMENT

Pull request to scheduled production

GitHub Actions parses and validates the dbt project on pull requests. The production-hardening change was validated in DEV, merged through a PR, deployed to Production, verified in Snowflake and left on a 12-hour dbt Cloud schedule.

MODEL OUTPUT

Business-facing marts.
